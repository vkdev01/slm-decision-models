Model comparison

How SLMs compare with each other, with frontier APIs and with non-neural baselines — on decision metrics, not benchmarks.

On this page

The useful comparison is not "which model scores highest on MMLU". It is "which model gives the lowest cost per case at my latency budget and my abstain capacity". Those are different questions with different winners.

Baselines you must include

  1. Majority class. Establishes the floor. If your model does not beat it by 10 points, something is broken.
  2. TF-IDF + logistic regression. Absurdly strong on text classification; frequently within 2–5 points of a fine-tuned transformer at 1/1000th the cost.
  3. Gradient boosting on engineered features. The incumbent in most enterprises.
  4. Frontier API with a good prompt. The quality ceiling and the cost comparison.
If the SLM does not beat the logistic baseline, ship the logistic baseline This happens more often than vendors would like. It is a success — you saved a year of model maintenance.

Illustrative. The pattern to expect: most of the gain arrives by 66M; the frontier API adds ~2 points of F1 over a distilled 360M model at 20× the latency and materially higher cost.

Reading that table honestly

  • 0.74 → 0.83 is the big jump. Almost all the value of "using a transformer" is captured by the smallest model in the list.
  • 0.83 → 0.88 is diminishing. Ask what those 5 points are worth in cost terms before paying 20× latency.
  • Cost per case, not F1, orders the last four rows. A 1.7B model is not worth 3× the latency for 1 point of F1 on a routing task.

Comparing like for like

# the only fair comparison: same spec, same split, same policy class
from slm_decision import evaluate_policy, CostOptimalPolicy

rows = []
for name, proba in scores_by_model.items():
    policy = CostOptimalPolicy(spec, max_abstain_rate=0.25)
    r = evaluate_policy(spec, policy, y_true=y_test, probs=proba)
    rows.append({"model": name, **r.to_dict()})

Keep the policy and the abstain cap fixed across models, otherwise you are comparing policies, not models. Then vary one axis at a time — accuracy, latency, memory — and record the hardware.

Distillation ladder

A practical sequence that avoids over-building: logistic baseline → 66M encoder → distill the best available teacher into 360M → stop. Each rung should be justified by a measured gain in cost per case, not by a benchmark leaderboard.
