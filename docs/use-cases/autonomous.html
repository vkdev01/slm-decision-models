Autonomous systems

Where the SLM advises and the classical stack decides — the safety architecture that keeps a language model out of the control loop.

On this page

In vehicles, drones and robots, an SLM does not drive. It converts messy human context — a passenger request, a maintenance note, a scene description — into structured intent that a deterministic planner can act on. The separation is not conservatism; it is the only way to get a certifiable system.

Architecture: SLM outside the loop

perception ──► planner ──► controller ──► actuators      (deterministic, certified)
                  ▲
                  │  structured intent, low rate (≤ 2 Hz)
                SLM decision layer                        (probabilistic, monitored)

The SLM never emits a control value. It emits an intent from a closed enumeration, which the planner validates against safety constraints before acting. If the intent is invalid or late, the planner falls back to a safe nominal behaviour — that fallback is the design, not the exception path.

Guardrails, in code

ALLOWED = {"reroute", "stop", "continue", "clarify"}

def slm_intent(context, timeout_ms=250):
    try:
        raw = slm.decide(context, timeout_ms=timeout_ms)
    except TimeoutError:
        return "hold_nominal"                       # fail safe, not fail open
    if raw.action not in ALLOWED:
        return "hold_nominal"
    if raw.confidence < 0.55:
        return "clarify"                            # ask the human, do not guess
    if not planner.is_safe(raw.action, context):     # deterministic veto
        return "hold_nominal"
    return raw.action
  • Hard timeout on every model call; the safe behaviour is always available without the model.
  • Deterministic veto: the planner can reject any SLM intent, and does so on constraint violation.
  • Closed action space, schema-validated, with an explicit unknown branch.
  • No model update without a re-run of the scenario suite and a shadow-mode period.
  • Every intent logged with model version, input hash, confidence and the planner's accept/reject.

Certification is the constraint, not the model ISO 26262 (automotive), DO-178C (airborne) and IEC 61508 (industrial) do not currently provide a route to certify a learned component in a safety-critical function. Keep the SLM in an advisory, low-rate, human-supervised role, and keep the certified stack deterministic. Anything else is a research programme, not a product.

Simulation before silicon

Test in simulation with adversarial scenarios, then in shadow mode on real vehicles with the SLM's output logged but not actuated. Compare the SLM's suggested intent against what the human operator actually did — that agreement rate is your readiness metric, and it is cheap to collect.
