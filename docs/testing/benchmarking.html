Benchmarking

Latency, throughput and cost measured honestly — plus the harness that keeps your numbers comparable across runs.

On this page

Benchmark claims decay fast and are easy to fake accidentally. This chapter is about measuring so that two runs a month apart are comparable: same harness, same warm-up, same reporting shape.

What to measure

MetricDefinitionWhy it matters
p50 / p95 / p99 latencyPer-request wall time, warmThe p99 is what your SLA is written against
ThroughputRequests per second at fixed concurrencySizing and cost per case
Time to first tokenGeneration models onlyDominates perceived latency in interactive use
Peak RSSResident memory after warm-upContainer sizing, edge fit
Cold startLoad + first inferenceAutoscaling and serverless viability
Energy (optional)Joules per 1k decisionsEdge and battery-powered deployments

Harness rules

  1. Warm up. Run 20 requests and discard them. First-call latency includes allocator and cache effects that never recur.
  2. Fix the input distribution. Benchmark on your real length distribution, not on 128-token sentences, unless you say so.
  3. Batch honestly. Batch-1 latency and batch-32 throughput are different products. Report both, labelled.
  4. Pin the environment. Threads (OMP_NUM_THREADS), quantisation, dtype, and the exact commit.
  5. Repeat. Three runs, report the median of the p95s, and note the spread.

Minimal harness

import time, statistics, numpy as np, torch

def benchmark(fn, inputs, warmup=20, repeat=3):
    for x in inputs[:warmup]:
        fn(x)
    runs = []
    for _ in range(repeat):
        ts = []
        for x in inputs:
            t0 = time.perf_counter(); fn(x); ts.append((time.perf_counter() - t0) * 1000)
        runs.append({"p50": np.percentile(ts, 50), "p95": np.percentile(ts, 95),
                     "p99": np.percentile(ts, 99), "mean": statistics.mean(ts)})
    return {k: statistics.median([r[k] for r in runs]) for k in runs[0]}

torch.set_num_threads(4)
res = benchmark(lambda t: model.decide(t), sample_texts)
print({k: round(v, 1) for k, v in res.items()})

Report cost per case alongside accuracy in every table. A policy that is 3 points less accurate but halves cost per case is usually the right choice, and the table should make that visible without a footnote.
