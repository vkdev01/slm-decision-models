Gaming

NPC behaviour, difficulty and dialogue where the decision must be fast, varied and never break character.

On this page

Games are the domain where an SLM's decision model is judged on experience rather than cost. The constraints are unusual: sub-frame latency for gameplay, variety as a feature (determinism is a bug), and a hard requirement that output never escapes the game's tone or lore.

Decision inventory

DecisionActionsLatencyNotes
Combat stanceaggressive · defensive · flank · flee · call-allies< 16 msUse a tiny classifier on state features; no generation

The pattern: classify, then template

Generating dialogue at 60 fps is not viable. Classify the situation with a small model and render from an authored template bank — the model chooses which line, the writers control what the line says.

spec = DecisionSpec(
    name="npc_stance",
    actions=["aggressive", "defensive", "flank", "flee", "call_allies"],
    costs={("aggressive","won"): 0, ("aggressive","lost"): 40,
           ("defensive","won"): 8,  ("defensive","lost"): 8,
           ("flee","won"): 60,      ("flee","lost"): 0},
    abstain="defensive",
)
# state features -> 5-way logits -> action, 4 ms on CPU at batch 1

Keeping it in character

Two mechanisms, both cheap:

  1. Closed action space + template bank. The model can only choose an action id; the writers own every string the player reads. Nothing can be emitted out of character.
  2. Banned-token masking if you must generate text: logits for lore-breaking tokens are set to −∞ before sampling. Cheap, effective, and auditable.

Determinism is a bug here

Unlike finance, variety is the point. Use temperature 0.8–1.0 with a seeded RNG per encounter, so a replayed encounter is reproducible for debugging while fresh encounters feel different. Store the seed with the save file — that is what makes bug reports actionable.

Testing in games

  • Simulation harness: run 10,000 synthetic encounters, assert win rates stay inside a designed band.
  • Character conformance: an automated check that no chosen template is tagged out-of-character for the NPC.
  • Latency p99 under load: test with the frame budget, not in isolation — a 9 ms decision in a 16 ms frame leaves little room for everything else.
  • Degenerate-strategy detection: verify the policy does not collapse to one action after tuning (entropy of the action distribution over a simulated session).
