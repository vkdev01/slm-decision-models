Overview

A practical, end-to-end guide to turning small language models (SLMs) into decision systems you can test, measure and ship.

A language model becomes a decision model the moment its output is used to pick an action. That single change raises the bar: a chat model can be "roughly right", a decision model cannot. It must return a defined label or action, with a calibrated confidence, an explicit abstain option, a bounded latency, and a documented failure mode for every input it will see in production.

This site is the written companion to the slm-decision-models repository. Every chapter follows the same shape: the concept, the maths, the numbers you should expect, a working code path, and the test that proves it still works after your next change.

What "decision model" means here

A decision model is a function from a messy observation to a committed action under uncertainty. Formally, with observation $$x$$, action space $$A$$, and a utility function $$u(a, y)$$ over the true outcome $$y$$:

a* = argmax_a  E_{p(y|x)}[ u(a, y) ]

Three properties separate this from ordinary text generation:

PropertyChat modelDecision model
Output spaceOpen textClosed set of labels or actions, schema-validated
UncertaintyImplicit, usually uncalibratedExplicit score + calibration check (ECE, reliability curve)
Failure handlingFree-form apologyAbstain / escalate, with a defined escalation path
EvaluationHuman preference, LLM-as-judgeCost-weighted accuracy, regret, coverage at fixed risk
Latency budgetSeconds, toleratedp95 budget enforced, usually 20–800 ms

Numbers to keep in your head

These are published reference points, not results measured on your data. Reproduce them with the scripts in benchmarks/ before quoting them internally.

QuantityReference valueSource / caveat

LoRA trainable parameters0.01%–1% of full weightsHu et al., 2021 — rank 8–64 adapters on attention projections
INT8 weight memory4× smaller than FP32, 2× smaller than FP16Arithmetic, not a benchmark: 1 byte vs 4 bytes per weight
INT4 weight memory8× smaller than FP32Quality loss is task-dependent; always re-run the eval suite
Calibration gapModern deep nets are typically over-confident; ECE of 0.05–0.15 is common pre-calibrationGuo et al., 2017 — measure your own ECE, never assume
Conformal guaranteeCoverage ≥ 1 − α on exchangeable dataAngelopoulos & Bates, 2021 — distribution-free, but assumes exchangeability

Read this before trusting any table Every performance table in this site is either attributed to a published paper or marked illustrative. Latency and accuracy depend on your hardware, your tokenizer, your label set and your data. The repo ships the scripts; run them on your machine and replace the numbers.

Sixty-second taste

from slm_decision import DecisionSpec, RulePolicy, calibrate, expected_cost

spec = DecisionSpec(
    actions=["approve", "review", "decline"],
    costs={("approve", "bad"): 10.0, ("decline", "good"): 3.0, ("review", "good"): 0.5},
    abstain="review",
)

# A policy is anything that maps a signal in [0,1] to an action under a cost matrix.
policy = RulePolicy(spec, threshold=0.62)
print(policy.act(0.71))          # 'approve'
print(expected_cost(spec, policy, y_true=[1, 0, 1], scores=[0.71, 0.55, 0.9]))
Working code, not pseudocode Everything importable here exists in code/src/slm_decision/ and is covered by the test suite. If a snippet on this site drifts from the library, the test suite is the source of truth — and CI will tell you.
